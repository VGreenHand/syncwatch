# SyncWatch Windows 客户端 GUI 设计文稿

> 状态：**已实施（v0.5）**，代码位于 `gui/`  
> 适用对象：Windows 10 / 11 桌面客户端  
> 设计目标：将原来“控制台问答 + 独立 mpv 窗口”升级为单窗口一体化应用  
> 技术路线：Wails v2 + React/TypeScript + mpv 通过 `--wid` 嵌入子窗口（已验证可行，结论见文末）

---

## 1. 已确认的产品决策

| 决策项 | 结论 |
|---|---|
| 产品形态 | 单窗口一体化，视频、房间信息和播放控制位于同一应用 |
| 全屏模式 | 沉浸式自动隐藏，移动鼠标或快捷键唤出控制界面 |
| 入房流程 | 首页提供“创建房间”和“加入房间”两个明确入口 |
| 选片时机 | 创建或加入前必须选择本地视频 |
| 播放权限 | 所有成员均可播放、暂停、拖动进度和调速 |
| 视觉方向 | 克制的深色影院风，遵循 Windows 11 Fluent 交互习惯 |
| 播放页布局 | 顶部状态、中央视频、底部控制、右侧可收起成员面板 |
| 异常反馈 | 主界面简洁提示，技术细节进入可展开的运行日志 |
| 技术路线 | 保留 Go 核心，优先验证 Wails + Web 前端 + mpv 单窗口嵌入 |
| 兼容策略 | GUI 默认启动，保留命令行参数和控制台调试入口 |
| 首版范围 | 现有能力完整 GUI 化，不增加聊天、踢人、自动更新等功能 |
| 本轮交付 | 设计文稿，不修改产品代码 |

## 2. 设计目标与边界

### 2.1 设计目标

1. **让第一次使用的人不再依赖说明文档**：创建与加入房间的意图清晰，不使用“留空代表创建”等隐式规则。
2. **让观影成为界面中心**：视频占据主要面积，房间功能随时可用但不持续干扰观看。
3. **让同步状态可感知**：用户能看懂谁在线、谁在缓冲、谁刚刚操作，以及自己是否已经断线。
4. **保留现有稳定性**：WebSocket 协议、服务端权威状态、漂移纠正和 mpv IPC 逻辑尽量复用。
5. **建立长期可维护的 UI 基础**：颜色、字号、间距、组件和事件均有统一规范，避免逐页临时设计。

### 2.2 首版不做

- 文字或语音聊天；
- 房主踢人、房间锁、仅房主控制；
- 自动更新和账号系统；
- 视频文件互传、在线流媒体或 P2P 分发；
- 为追求视觉效果而引入大量玻璃、霓虹、粒子和无意义动效；
- 同步协议或服务端功能重构。

## 3. 信息架构

应用由四个主层组成：

```text
首页
├── 创建房间
│   ├── 选择本地视频
│   ├── 昵称与可选密码
│   └── 创建并连接
├── 加入房间
│   ├── 输入房间码与可选密码
│   ├── 选择本地视频
│   └── 加入并同步
├── 播放房间
│   ├── 视频与播放控制
│   ├── 房间码与连接状态
│   ├── 成员与片源状态
│   └── 操作通知与异常提示
└── 设置 / 运行日志
    ├── 常规设置
    ├── 服务器与 mpv 高级设置
    └── 日志查看、复制与导出
```

页面切换遵循单向主路径：

```text
首页 → 创建/加入 → 连接中 → 播放房间 → 离开确认 → 首页
                         ↘ 可恢复错误：停留在当前页并提供重试
```

## 4. 核心页面与线框

### 4.1 首页

首页不堆砌功能介绍。主视觉是产品名称、一句价值说明和两个任务入口。

```text
┌──────────────────────────────────────────────────────────────┐
│  一起看 · SyncWatch                              设置  日志 │
│                                                              │
│                 和朋友，看同一时刻。                         │
│             本地视频不上传，只同步播放控制。                 │
│                                                              │
│          昵称  [ 观众________________________ ]              │
│                                                              │
│          ┌──────────────────┐  ┌──────────────────┐          │
│          │  +  创建房间      │  │  →  加入房间      │          │
│          │  选择视频并邀请朋友│  │  输入朋友的房间码 │          │
│          └──────────────────┘  └──────────────────┘          │
│                                                              │
│             服务器：已配置                       高级设置     │
└──────────────────────────────────────────────────────────────┘
```

设计要求：

- 默认窗口建议为 1120 × 720，最小窗口为 900 × 600；
- 主内容最大宽度约 760px，避免宽屏上表单无限拉伸；
- “创建房间”和“加入房间”使用同等视觉权重；
- 昵称记住上次内容，但允许随时修改；
- 服务器地址只显示“已配置 / 未配置 / 无法连接”等摘要，详细值收进高级设置；
- 首页支持拖入视频：拖入后根据用户下一步点击创建或加入继续流程，不自动创建房间。

### 4.2 创建房间

```text
┌──────────────────────────────────────────────────────────────┐
│  ← 返回                 创建房间                             │
│                                                              │
│  本地视频 *                                                  │
│  ┌────────────────────────────────────────────────────────┐  │
│  │  拖入视频，或点击选择文件                               │  │
│  │  支持 mpv 可播放的本地格式                              │  │
│  └────────────────────────────────────────────────────────┘  │
│  已选择：电影.mkv    02:05:31 · 4.2 GB · MKV      重新选择   │
│                                                              │
│  昵称 *       [ 观众________________________ ]                │
│  房间密码     [ 可选________________________ ]                │
│  高级设置     服务器地址、mpv 路径                 展开 >     │
│                                                              │
│  错误提示区：仅在有错误时出现                                 │
│                                      [ 创建并开始观看 ]       │
└──────────────────────────────────────────────────────────────┘
```

交互规则：

- 视频为必填项；未选择时主按钮可点击，但点击后聚焦并提示缺失项，避免按钮无解释地长期禁用；
- 文件选中后立即读取文件名、大小、时长和格式；
- 文件不存在、无法读取或 mpv 不可用时，在按钮上方给出具体处理建议；
- 密码明确标注“可选”，不使用留白猜测；
- 创建期间按钮进入加载态，禁止重复提交；
- 创建成功后进入播放页，房间码醒目显示并提供复制按钮，不再依赖控制台横幅。

### 4.3 加入房间

创建页结构复用，但第一项任务改为房间码：

- 房间码使用较大字号和等宽数字字母；
- 自动去除首尾空格并转为大写；
- 允许直接粘贴完整房间码；
- 房间码、密码、视频均通过本地校验后再发起连接；
- 如果服务端将不存在的房间创建为新房，必须弹出明确阻断式提示：

```text
没有加入朋友的房间
你输入的房间码 ABC123 不存在或已解散，本次创建了一个新房间。
[ 留在新房间 ]  [ 返回重新输入 ]
```

该提示不能只用一闪而过的 Toast。

### 4.4 连接中

连接中使用当前页面内的状态面板，不制造长时间无反馈：

```text
正在加入房间 ABC123
✓ 视频已载入
✓ 播放器已就绪
→ 正在连接服务器…
○ 正在同步房间进度

[ 取消 ]
```

失败时保留用户已填写的信息，并提供“重试”“修改服务器”“查看详情”。

### 4.5 播放房间：普通窗口

```text
┌──────────────────────────────────────────────────────────────┐
│  电影.mkv       房间 ABC123 [复制]      ● 已连接      全屏  │
├───────────────────────────────────────────────┬──────────────┤
│                                               │ 房间成员  3/5│
│                                               │              │
│                                               │ 你            │
│                                               │ ● 正在播放    │
│                 视 频 区 域                   │ 02:05:31      │
│                 16:9 / 原始比例               │              │
│                                               │ 小明          │
│                                               │ ● 正在播放    │
│                                               │ 02:05:31      │
│                                               │              │
│                                               │ 小红          │
│                                               │ ◌ 正在缓冲    │
│                                               │ 时长不一致    │
├───────────────────────────────────────────────┴──────────────┤
│  [播放/暂停]  00:42:18  [──────进度──────]  02:05:31  1.0× │
│  [音量]  [字幕]  [成员]                         [离开]       │
└──────────────────────────────────────────────────────────────┘
```

布局规范：

- 顶栏高度建议 56px；底部控制区建议 64–76px；
- 右侧成员面板默认 280px，可收起，收起状态记忆到本次会话；
- 视频区纯黑，按比例缩放，不拉伸、不裁切；
- 进度条为最主要的拖动控件，悬停时扩大有效触控区域；
- 主按钮只保留一个强强调色，其余按钮采用低强调样式；
- 离开房间需要确认，确认框说明“只退出当前房间，不删除本地视频”。

### 4.6 全屏模式

- 默认只显示视频；
- 鼠标静止约 2 秒或键盘无操作时，光标和控制界面隐藏；
- 移动鼠标、点击或按空格时显示控制界面；
- 顶部浮层显示片名、房间码缩写和连接状态；
- 底部浮层显示播放、进度、音量、倍速和退出全屏；
- 成员面板以右侧浮层形式展开，关闭后恢复纯视频；
- 断线重连等关键状态即使控制条隐藏，也应以顶部轻量状态条提示；
- `Esc` 优先关闭成员浮层，其次退出全屏；避免一键触发多个行为。

## 5. 组件与交互规范

### 5.1 播放控制

| 控件 | 行为 |
|---|---|
| 播放/暂停 | 切换全房间状态；按钮图标表示下一步动作 |
| 进度条 | 拖动时只预览本地目标时间，松开后发送一次同步请求 |
| 当前时间 / 总时长 | 使用等宽数字，避免播放时布局抖动 |
| 倍速 | 提供 0.5×、0.75×、1.0×、1.25×、1.5×、2.0× |
| 音量 | 仅影响本地，不同步给其他成员 |
| 字幕 | 首版只调用已有 mpv 能力，不设计在线字幕下载 |
| 全屏 | 当前显示器进入/退出全屏，保留窗口尺寸记忆 |
| 成员 | 展开或收起成员面板 |
| 离开 | 二次确认后停止同步并关闭播放器 |

任何远端操作都应以非阻断通知说明来源：

- “小明暂停了播放”；
- “小红将进度跳转到 42:18”；
- “服务器已纠正你的播放进度”。

普通操作通知 3–4 秒后消失；错误和需要决策的提示不能自动消失。

### 5.2 成员项

每个成员项包含：

1. 昵称与“你”的标识；
2. 在线、离线、播放、暂停、缓冲状态；
3. 文件时长或文件信息摘要；
4. 片源时长不一致警告。

状态不能只靠颜色区分，必须同时使用图标和文字。成员进出时使用 120–180ms 的淡入淡出，不播放夸张动画。

### 5.3 连接状态

| 状态 | 展示 | 主操作 |
|---|---|---|
| 已连接 | 顶栏绿色状态点 +“已连接” | 无 |
| 正在连接 |  Spinner + 当前阶段 | 取消 |
| 正在重连 | 顶部黄色横幅 + 重连次数 | 查看详情 |
| 重连失败 | 红色错误面板 | 重试 / 返回首页 |
| 播放器断开 | 与网络错误区分显示 | 重启播放器 / 查看日志 |
| 片源异常 | 成员面板或视频上方警告 | 查看成员片源信息 |

### 5.4 设置

首版设置分为两组：

- **常规**：昵称、窗口尺寸记忆、通知开关；
- **高级**：服务器地址、mpv 路径、启动参数、运行日志。

密码、房间码和完整视频路径不应写入普通日志。日志默认只保留当前会话，可由用户主动复制或导出。

## 6. 视觉系统

### 6.1 设计原则

- **影院感来自留白和层级，不来自光效。**
- **视频之外使用深灰蓝，视频区域才使用纯黑。**
- **主色用于行动和焦点，不用来铺满背景。**
- **所有状态均有文字或图标，不仅靠颜色。**
- **优先保证中文在 Windows 下的清晰度。**

### 6.2 建议色彩变量

| 语义 | 建议值 | 用途 |
|---|---|---|
| `bg-app` | `#101216` | 应用最底层背景 |
| `bg-surface` | `#171A21` | 卡片、侧栏 |
| `bg-elevated` | `#20242D` | 浮层、弹窗 |
| `video-black` | `#000000` | 视频显示区域 |
| `border-subtle` | `#2B303B` | 分隔线、输入框边界 |
| `text-primary` | `#F3F5F8` | 主文本 |
| `text-secondary` | `#A8B0BD` | 次要说明 |
| `accent-primary` | `#7C8CFF` | 主按钮、焦点、进度 |
| `accent-hover` | `#929FFF` | 主色悬停 |
| `state-success` | `#42C98A` | 已连接、成功 |
| `state-warning` | `#E7B65A` | 重连、片源警告 |
| `state-error` | `#F07478` | 错误、失败 |

以上颜色是首版设计基线，实施时需做实际对比度检查；正文和关键控件目标达到 WCAG AA。颜色必须集中在主题变量中，页面不得散落硬编码色值。

### 6.3 字体与排版

- 中文首选：`Microsoft YaHei UI`；
- 英文与数字回退：`Segoe UI`；
- 房间码、时间、日志使用等宽字体：`Cascadia Mono` 或系统回退；
- 页面标题 24px / 32px，区块标题 16px / 24px，正文 14px / 22px，辅助文字 12px / 18px；
- 播放时间使用等宽数字特性；
- 正文不小于 12px，播放控制的主要文字建议不小于 14px。

### 6.4 圆角、间距与阴影

- 采用 4px 基础间距体系：4、8、12、16、24、32、48；
- 输入框和小按钮圆角 6px，卡片 10px，弹窗 12px；
- 阴影只用于浮层和弹窗，普通卡片主要依靠背景与边界分层；
- 动画时长以 120–200ms 为主，只使用透明度、位移和尺寸的必要过渡；
- 遵循系统“减少动画”设置。

### 6.5 图标与可访问性

- 使用统一线性图标集，不混用 Emoji、文本符号和多套图标；
- 图标按钮必须有悬停提示和可访问名称；
- 所有核心功能可键盘访问，焦点环清晰可见；
- 空格控制播放/暂停，左右方向键控制进度时必须避免与输入框编辑冲突；
- 100%、150%、200% DPI 下检查文本截断、视频区域和弹层位置。

## 7. 技术落地建议

### 7.1 推荐技术组合

- 桌面壳：Wails；
- 前端：React + TypeScript + Vite；
- 样式：CSS Variables + 模块化样式，首版不引入重型 UI 框架；
- 状态：按页面使用明确的状态模型，房间、连接和播放器状态由 Go 事件驱动；
- 后端：复用现有 Go WebSocket、房间状态、心跳、重连与 mpv IPC 逻辑；
- 播放内核：继续使用 mpv，不在 GUI 改版中同时更换解码内核。

前端不直接拼装 WebSocket 协议消息，所有同步行为通过 Go 暴露的方法进入同步核心。

### 7.2 建议模块边界

```text
Windows 应用
├── Wails 生命周期与窗口管理
├── 房间应用服务
│   ├── 创建 / 加入 / 离开
│   ├── 配置校验
│   └── 向 UI 发送结构化事件
├── 同步核心（尽量复用现有逻辑）
│   ├── WebSocket 与协议
│   ├── 心跳与重连
│   └── 回声抑制与漂移处理
├── 播放器适配层
│   ├── mpv 启停与 IPC
│   ├── 窗口嵌入与尺寸同步
│   └── 播放、暂停、seek、倍速、音量
└── React 界面
    ├── 首页与入房流程
    ├── 播放页与成员面板
    ├── 设置与日志
    └── 主题组件与通知系统
```

现有 `main.go` 中的业务逻辑不宜直接复制进 UI 回调。应先把同步核心与控制台输出解耦，再让 GUI 和调试入口共同调用同一核心。

### 7.3 Go 与 UI 的接口方向

建议至少覆盖以下方法：

- 选择视频、读取文件信息；
- 创建房间、加入房间、取消连接、离开房间；
- 播放/暂停、跳转、倍速、音量、全屏；
- 复制房间码、打开设置、读取和保存配置；
- 获取日志、复制诊断信息。

Go 向 UI 推送的事件至少包括：

- 连接阶段与重连状态；
- 当前房间与操作结果；
- 播放状态与播放器可用性；
- 成员列表及片源状态；
- 远端操作通知；
- 可展示错误与诊断日志。

要求：

- UI 事件不得阻塞 WebSocket 读取循环；
- 不在后台 goroutine 中直接 `os.Exit`，错误需返回统一生命周期处理；
- 窗口调用和原生句柄操作遵守 Wails / Windows 的线程要求；
- 前端只保存展示状态，权威房间状态仍以服务端和 Go 核心为准。

## 8. 单窗口播放器嵌入：正式开发前的技术闸门

这是项目最高优先级的技术验证，不应等 UI 全部完成后才处理。

### 8.1 最小原型只验证播放器

原型不需要完整皮肤，只包含一个原生窗口、嵌入的视频区域、一个播放按钮、一个浮动控制条和全屏切换。

重点验证：

1. Wails 窗口中能否稳定获取并使用正确的原生窗口句柄；
2. mpv 嵌入后是否能随窗口缩放、最大化、拖动和 DPI 变化正确重排；
3. HTML 控制层能否在普通窗口和全屏中覆盖视频；需特别验证 WebView2 与原生视频子窗口的层级/空域问题；
4. 视频是否出现黑屏、闪烁、残影、错误缩放或鼠标穿透；
5. 空格、方向键、Esc、鼠标双击是否发生焦点冲突；
6. 多显示器、不同 DPI、全屏切换是否正常；
7. 退出、重连和播放器异常退出后，是否残留 mpv 进程或失效句柄。

### 8.2 通过标准

- 普通窗口与全屏均能显示浮动控制条；
- 100% / 150% / 200% DPI 下画面比例和控制位置正确；
- 连续调整窗口、切换全屏、拖动进度和暂停播放无黑屏或失控；
- 鼠标与键盘焦点行为符合第 4–5 章设计；
- 退出后无残留播放器进程；
- 验证过程形成简短结论和可复现测试记录。

如果关键项无法通过，暂停完整 Wails UI 开发，评审“Windows 原生宿主 + 保留 Go 同步核心”的替代承载方案。**不能退回独立 mpv 窗口来冒充单窗口目标，也不能靠牺牲全屏控制条来规避问题。**

## 12. 实施记录（v0.5）

### 12.1 技术闸门结论：通过

第 8 章要求的关键验证全部通过，实测数据：

| 验证项 | 结果 |
|---|---|
| 获取 Wails 主窗口句柄 | 按类名 `wailsWindow` + PID 匹配（`OnDomReady` 时窗口可能尚未显示，不能靠 `IsWindowVisible`） |
| mpv 嵌入 | 用 `--wid=<自建 STATIC 子窗口>`，mpv 子窗口尺寸与宿主完全一致 |
| 窗口缩放跟随 | 1000×700 / 1400×900 / 1120×720 三档，宿主等比变化，无黑屏 |
| HTML 控制层覆盖视频 | WebView2 `WebviewIsTransparent=true` + 页面容器**不设背景色**，控制条正常叠在画面上 |
| 拖进度、暂停无回声 | 服务端日志只出现一次 `[msg] <昵称> play/pause`，无 A→B→A 循环 |
| 退出无残留 | `LeaveRoom` 关闭 IPC 并 kill mpv，进程列表无残留 |

### 12.2 实施中踩到的坑（都已修在代码里）

1. **窗口线程**：`CreateWindowEx` 创建的窗口归属调用线程，而 Go goroutine 会飘。跨线程 `ShowWindow` 会同步阻塞且没有超时——实测直接把加载流程卡死。解决：所有 Win32 窗口操作投递到 `runtime.LockOSThread()` 的专用线程串行执行（`gui/win32.go`）。
2. **容器背景色会吃掉视频**：`.app` / `.stage` 只要设了 `background`，就会把下层 mpv 完全盖住（WebView2 在这一层之上）。两个容器必须保持 `transparent`，只让顶栏、控制条自己带底色。
3. **选片早于播放页**：创建/加入房间前就要载入视频，但视频区在播放页才渲染。解决：`LoadVideo` 先建一个 1×1 隐藏宿主把 mpv 拉起来，进播放页后由 `SetVideoRect` 摆正。
4. **mpv 启动即播放**：初始 `pause=false` 会被当成用户点了播放，把房间状态改成 playing 并触发漂移纠偏。解决：启动参数加 `--pause=yes`。
5. **属性事件要用数字 id**：`observe_property` 用字符串当 id 时事件里 `name` 为空，解析不到；改用 1..6 的整数 id。
6. **重复载入**：Go 侧与前端各有一套自动载片入口，导致同时拉起两个 mpv（同一个管道名互相抢占）。解决：只保留前端的调试入口，`LoadVideo` 加并发保护，管道名加序号。
7. **底部状态栏不显示**：状态栏所在的 30px 区域会被 mpv 的 D3D 表面覆盖（WebView2 透明合成 + 子窗口的已知问题，红色背景也显示成黑色）。解决：取消独立状态栏，把进度/时长并入顶部浮层，进度条本身已有时间显示。

### 12.3 与原设计的差异

| 设计稿 | 实现 | 原因 |
|---|---|---|
