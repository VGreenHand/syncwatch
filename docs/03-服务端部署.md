# 服务端部署与运维

服务端是**无状态**的单二进制（房间只存在内存里），部署极其轻量：一台 1 核 1G 的云主机足够跑几十个房间。

## 0. 前置条件

- Linux 云主机（本项目实测 Alibaba Cloud Linux 3 / x86_64，其他发行版同理）
- 已安装 Docker 20+ 与 docker compose v2（`docker compose version` 有输出）
- 安全组/防火墙放行一个 TCP 端口（默认 8995）

```bash
# 检查
docker --version && docker compose version
```

> 当前登录用户需要有 docker 权限。若报 `permission denied`，把用户加入 docker 组后**重新登录**：
> `sudo usermod -aG docker $USER`

## 1. 方式一：Docker Compose（推荐）

```bash
git clone <你的仓库地址> && cd syncwatch/server
cp .env.example .env
vi .env                      # 端口、镜像源按需修改
docker compose up -d --build
docker compose ps
curl http://127.0.0.1:8995/health    # {"status":"ok","rooms":0}
```

容器特性（已写在 `docker-compose.yml`）：

- `restart: unless-stopped` —— 主机重启后自动拉起
- `read_only: true` + 非 root 用户 —— 只读根文件系统，降低被入侵后的影响面
- `mem_limit 256m` / `cpus 0.5` —— 就算被打爆也拖不垮主机
- 日志轮转 10MB × 3 —— 不会写满磁盘
- 健康检查 —— `docker ps` 直接看 healthy

### .env 变量

| 变量 | 默认 | 说明 |
|------|------|------|
| `PORT` | 8995 | 宿主机监听端口（容器内固定 8995） |
| `GO_IMAGE` | `golang:1.22-alpine` | 构建阶段基础镜像 |
| `RUNTIME_IMAGE` | `alpine:3.20` | 运行阶段基础镜像 |
| `GOPROXY` | `https://proxy.golang.org,direct` | Go 模块代理 |

### 国内服务器必看

Docker Hub 与 proxy.golang.org 在大陆通常不可直连，`.env` 里换成：

```ini
GO_IMAGE=docker.m.daocloud.io/library/golang:1.22-alpine
RUNTIME_IMAGE=docker.m.daocloud.io/library/alpine:3.20
GOPROXY=https://goproxy.cn,direct
```

（`docker.m.daocloud.io` 是已验证可用的镜像源之一；若失效换 `docker.1ms.run` 等，前缀规则相同。）

## 2. 方式二：裸二进制 + systemd（不用 Docker）

```bash
cd server
CGO_ENABLED=0 go build -trimpath -ldflags="-s -w" -o syncwatch-server .
sudo install -m 755 syncwatch-server /usr/local/bin/
sudo useradd -r -s /sbin/nologin syncwatch || true
sudo tee /etc/systemd/system/syncwatch.service >/dev/null <<'EOF'
[Unit]
Description=SyncWatch signaling server
After=network.target

[Service]
User=syncwatch
Environment=PORT=8995
ExecStart=/usr/local/bin/syncwatch-server
Restart=always
RestartSec=3
NoNewPrivileges=true
ProtectSystem=strict
PrivateTmp=true

[Install]
WantedBy=multi-user.target
EOF
sudo systemctl daemon-reload && sudo systemctl enable --now syncwatch
systemctl status syncwatch --no-pager
```

## 3. 开放端口

云厂商的**安全组**和主机**防火墙**是两道独立的门，都要放行：

```bash
# 主机侧（firewalld 为例）
sudo firewall-cmd --add-port=8995/tcp --permanent && sudo firewall-cmd --reload
# 或 ufw
sudo ufw allow 8995/tcp
```

安全组：控制台 → ECS → 实例 → 安全组 → 入方向 → 手动添加
`协议 TCP`、`端口 8995/8995`、`授权对象 0.0.0.0/0`。

**只想自己人用**：授权对象改成你的常用出口 IP 段，暴露面更小。

验证外网可达（在你自己的电脑上）：

```bash
curl http://<服务器IP>:8995/health
```

## 4. 一键部署脚本

`server/deploy.sh` 把当前源码打包推到远端并重建容器，适合"改完代码想立刻上线"：

```bash
cd server
cp deploy.env.example deploy.env    # 填 host / port / user / 目录
./deploy.sh                          # 需要本机已配置 SSH 免密登录
```

脚本做的事：`tar` 打包源码 → `ssh` 传过去 → 远端 `docker compose up -d --build` → 打印健康状态。

> 首次使用前请确保本机公钥已装到远端 `~/.ssh/authorized_keys`（推荐做法，避免密码进命令行历史）。

## 5. 日常运维命令

| 目的 | 命令 |
|------|------|
| 看状态 | `docker compose ps` |
| 看日志（实时） | `docker compose logs -f --tail 100` |
| 重启 | `docker compose restart` |
| 升级代码 | `git pull && docker compose up -d --build` |
| 停服 | `docker compose down` |
| 资源占用 | `docker stats --no-stream` |
| 健康检查 | `curl -s localhost:8995/health` |

日志里的有用信息：

```
[room 7M8QW6] 小明 joined, 2 members          # 进房
[room 7M8QW6] drift 2.35s by 小红 -> forceSeek 1583.2   # 触发了纠偏，说明有客户端解码偏慢
```

`forceSeek` 频繁出现说明片源不一致或某端性能不足，属于排查线索而非错误。

## 6. 迁移到新机器（10 分钟）

因为服务端无状态，迁移就是"重装一遍"：

```bash
# 新机器
git clone <仓库> && cd syncwatch/server && cp .env.example .env && docker compose up -d --build
```

然后把客户端配置里的地址改成新 IP 即可（Windows 改 `server.txt`，Android 在 App 里改服务器地址）。
老机器 `docker compose down` 收工。

## 7. 安全加固清单

- [x] 只暴露一个端口，不用 80/443（也就不需要域名和 ICP 备案）
- [x] 房间人数上限 5，每连接 40 条/秒限流
- [x] 容器只读文件系统、非 root、内存/CPU 限额
- [ ] 房间密码（协议支持，客户端可选填；公共使用时建议开启）
- [ ] 定期 `docker compose pull`/重建，跟进基础镜像安全更新
- [ ] 服务器不做文件服务、不开代理，避免被扫到滥用

## 8. 排障

| 现象 | 排查 |
|------|------|
| 外网 `curl /health` 超时 | 安全组没放行 / 主机 firewalld 没放行 / 容器没起 |
| `docker compose up` 卡在拉镜像 | 国内网络，换 `GO_IMAGE`/`RUNTIME_IMAGE` 镜像源 |
| 容器 Up 但 `curl` 拒绝连接 | 端口映射写错，或 `PORT` 改了但防火墙没跟着改 |
| 客户端连上就断 | 看服务端日志是否有 `rate limit` / `bad json`；多为客户端版本不匹配 |
| 房间码输对了却"房间已满" | 上次异常断线残留的成员；等 60s 心跳超时自动清理，或重启容器 |
| 内存持续增长 | 每个房间几百字节，正常可忽略；异常增长请查是否有连接未释放（`docker stats`） |
