# Android 客户端现代化 UI 实施文稿

> 状态：已实施并通过 Android 模拟器与本地同步服务验证（v0.5.2-ui）  
> 前置设计：[07-Android客户端现代化UI设计.md](07-Android客户端现代化UI设计.md)  
> 目标：在不改服务端与同步协议的前提下，完成 UI、播放手势和手机/平板适配。

## 1. 已确认的实施边界

| 项目 | 决策 |
|---|---|
| UI 技术 | 保留 Kotlin + XML/View |
| 页面结构 | 保留单 `MainActivity`，适度拆分 UI 与手势组件 |
| 播放内核 | 继续使用 Media3 ExoPlayer |
| 同步协议 | 不修改 `Protocol.kt`、服务端和 Windows 端协议 |
| 最低系统 | minSdk 24，Android 7.0+ |
| 屏幕方向 | 手动竖屏/横屏，不自动旋转；横屏支持播放锁定 |
| 设备布局 | 手机单栏；600dp 起平板双栏；横屏成员抽屉 |
| seek 预览 | 时间预览，不做缩略图；松手后一次 seek |
| 功能扩展 | 不做字幕、音轨、投屏和画面比例设置 |

## 2. 当前实现与主要改造点

### 2.1 当前结构

| 文件 | 当前职责 | 本次改造重点 |
|---|---|---|
| `android/.../MainActivity.kt` | 首页、播放器、同步回调、文件选择、生命周期全部集中 | 保留流程协调，拆出控制层、手势和页面状态 |
| `android/.../SyncEngine.kt` | WebSocket、回声抑制、心跳、远端指令 | 原则上不改；只为 UI 增加必要的状态回调时做最小调整 |
| `android/.../Protocol.kt` | 消息构造与解析 | 不改 |
| `res/layout/activity_main.xml` | 单页表单 + 顶部成员栏 + 默认 `PlayerView` | 重组首页与播放页容器，移除默认控制层依赖 |
| `res/values/colors.xml` | 当前浅色主题色板 | 替换为深色设计令牌 |
| `res/values/themes.xml` | `AppCompat.Light.NoActionBar` | 改为深色 NoActionBar 主题并处理系统栏 |
| `AndroidManifest.xml` | `sensor` 旋转、已声明部分 configChanges | 改为手动方向策略，确认横竖屏切换不重建播放器 |

### 2.2 现有同步链路必须保留

当前本地 seek 链路是：

```text
Player.Listener.onPositionDiscontinuity(SEEK)
  → SyncEngine.onLocalSeek(position)
  → 回声抑制 / hello 检查
  → 发送 seek
```

新手势不要绕开播放器直接逐帧发网络消息。推荐链路：

```text
手指移动 → 只更新预览 UI
手指抬起 → player.seekTo(target) 一次
播放器产生 SEEK 事件 → 现有同步链路上报一次
```

现有 `SyncEngine` 对远端指令有约 400ms 的抑制窗口，并检查 `helloReceived`。实施时必须用真实双端验证“一次操作只广播一次”，不能仅凭代码推断。

## 3. 建议的代码组织

以下文件是实施时的建议新增或拆分结果，**本次文稿阶段并未创建这些代码文件**：

├── layout/activity_main.xml          # 手机竖屏主容器
├── layout/view_join_create.xml       # 创建面板（也可保留在主布局）
├── layout/view_join_room.xml         # 加入面板（也可保留在主布局）
├── layout/view_player_controller.xml # 自定义 Media3 控制层

不要为每个小视图机械地新建类。拆分的判断标准是：能否独立维护状态、独立测试，是否能降低 `MainActivity` 的耦合。

## 4. 页面状态与职责划分

### 4.1 页面状态

```text
Join(create/join)
  → Connecting
  → Player(portrait/landscape)
  → LeaveConfirmation
  → Join
```

连接失败或加入失败必须回到可修改的首页，不留下无法操作的半初始化播放页。

### 4.2 播放 UI 状态

建议由少量明确状态组成：

- `playing` / `paused` / `buffering`
- `controlsVisible`
- `isFullscreen`
- `isPlaybackLocked`
- `membersPanelOpen`
- `connectionState`
- `gesturePreview`：`None / Seek / Brightness / Volume`

播放锁定是本地 UI 状态，不与房间锁、远端状态混合。远端播放器事件仍直接更新播放状态。

### 4.3 回调方向

- 控制层只发出用户意图：播放、暂停、seek、倍速、全屏、锁定、打开成员。
- `MainActivity` 决定如何调用播放器或同步引擎。
- 播放器和 `SyncEngine` 的真实状态再回写控制层。
- 手势控制器不直接创建或发送协议消息。

## 5. 分阶段实施顺序

每个阶段完成后都应可构建、可回退，避免一次性重写后无法定位回归。

### 阶段 0：建立基线

1. 保存当前 APK 和可回退的代码分支。
2. 记录当前创建、加入、播放、暂停、seek、断线重连行为。
3. 用 Android 真机与 Windows 同房跑通基线。
4. 确认测试视频时长一致，准备长视频和短视频各一份。

**完成标准**：有一份可运行的旧版和一组可复现的同步基线结果。

### 阶段 1：主题、资源与首页

1. 将颜色、字号、间距、圆角整理为资源，不在布局中散落硬编码。
2. 将主题改为深色，逐项检查输入文字、hint、按钮和系统栏对比度。
3. 实现创建/加入分段切换及动态字段。
4. 将服务器地址移入高级设置，保留 SharedPreferences 配置键，避免升级后丢失用户配置。
5. 实现文件选择卡片、错误状态和主按钮动态文案。
6. 加入首页滚动与小屏/大字体适配。

**完成标准**：首页视觉完成，创建/加入行为与旧版一致，原服务器和昵称仍能读取。

### 阶段 2：自定义播放控制层

1. 关闭 `PlayerView` 默认控制器，保留其视频渲染能力。
2. 在 `PlayerView` 上层添加自定义控制层和上下渐变遮罩。
3. 接入播放/暂停、±10 秒、进度条、时间、倍速、全屏、房间码和成员入口。
4. 实现播放中 3 秒隐藏；暂停、缓冲、面板和手势期间保持。
5. 将普通 Toast 逐步替换为轻提示、持续状态条和阻断错误。
6. 保留意外创建房间的阻断提示。

**完成标准**：所有核心功能可由自定义控制层完成，默认控件不再重复出现，跨端控制无回归。

### 阶段 3：横滑 seek 与点按手势

1. 先实现并测试纯计算组件，再连接触摸事件。
2. 接入按下、方向判定、预览、松手、系统取消状态。
3. 加入单击与双击判定，保证控制按钮不等待双击。
4. 接入远端 seek 取消本地预览。
5. 验证 seek 前后播放状态保持、边界钳制和单次上报。

**完成标准**：横滑流畅、预览准确、松手只 seek 一次，双端无循环回声和跳回片头。

### 阶段 4：横屏、亮度/音量与锁定

1. 实现手动进入固定横屏和退出竖屏。
2. 处理沉浸模式、刘海、导航栏和手势安全区。
3. 实现左亮度、右音量及本机反馈。
4. 实现播放锁定和唯一解锁入口。
5. 实现横屏返回先退出、竖屏返回确认离开。

**完成标准**：不会自动旋转，锁定不妨碍远端同步，返回不意外退房。

### 阶段 5：平板与响应式布局

1. 用 600dp 资源分界提供平板首页和播放页。
2. 平板非全屏采用双栏，横屏采用成员抽屉。
3. 验证布局变化不释放播放器、不重连房间、不丢失文件 URI。
4. 测试手机、平板不同密度与字体缩放。

**完成标准**：平板不是拉伸版手机，旋转/尺寸变化后播放与房间状态保持。

### 阶段 6：回归与发布

1. 完成第 10 节的测试矩阵。
2. 检查 Android 7.0 或最接近的低版本设备/模拟器。

## 6. 横滑 seek 技术规则

### 6.1 手势状态

```text
Idle
  └─ ACTION_DOWN → Pressed
                    ├─ 水平方向确认 → Seeking
                    ├─ 横屏垂直方向确认 → Brightness / Volume
                    ├─ 单击 → ToggleControls → Idle
                    ├─ 双击 → TogglePlayback → Idle
                    └─ ACTION_CANCEL → Idle（不提交）
```

`Locked` 是独立的覆盖状态。进入锁定后取消当前手势，除解锁外不进入上述分支。

### 6.2 位移计算

```text
deltaMs = dxPx / gestureAreaWidthPx * 90_000
targetMs = clamp(gestureStartPositionMs + deltaMs, 0, durationMs)
```

- `gestureStartPositionMs` 只在 `ACTION_DOWN` 时读取一次。
- 预览过程中始终使用该起点，不能用当前预览值继续叠加。
- `dxPx > 0` 为快进，`dxPx < 0` 为快退。
- 视频时长未知或非正数时不进入 seek。
- 到片头/片尾后继续滑动只保持边界值，不回绕。

### 6.3 方向判定

- 使用 `ViewConfiguration.scaledTouchSlop` 作为系统基础阈值，设计目标约 10dp。
- 水平位移明显大于垂直位移才进入 seek；垂直手势采用对称规则。
- 一旦锁定主轴，本次触摸不再切换手势类型。
- 控件和进度条优先消费自己的触摸，不向画面手势透传。

### 6.4 提交与取消

| 事件 | 处理 |
|---|---|
| 正常松手且存在有效 seek 预览 | 执行一次 `player.seekTo(targetMs)` |
| `ACTION_CANCEL` | 清除预览，不执行 seek |
| 收到远端 seek | 清除预览，应用远端位置，松手不再提交 |
| 收到远端 play/pause | 正常应用播放状态，不上报为本地操作 |
| 播放锁定/退出播放页 | 取消预览，不提交 |
| 位移未超过阈值 | 走单击/双击判定，不 seek |

建议在实现中增加本次手势 ID 或明确的 `previewActive` 标志，远端取消后必须让后续 `ACTION_UP` 失效。

## 7. Media3 与同步注意事项

### 7.1 不重复上报

- 每次本地手势只调用一次播放器 seek。
- 不在手势 `onMove` 中调用 seek 或 `SyncEngine.onLocalSeek`。
- 不为同一目标同时调用“显式协议发送”和“播放器事件发送”两条链路。
- 保留现有远端 suppress 窗口，并验证双击播放/暂停不会形成回声。

### 7.2 保持播放状态

seek 只改变位置，不主动调用 `play()` 或 `pause()` 来“修复”状态。播放器 seek 导致短暂 `isPlaying=false` 时，不应被误判为暂停；当前监听逻辑已有相关防护，回归时必须覆盖。

### 7.3 进度条与手势统一

进度条拖动与画面横滑应共享目标时间格式化和边界规则，但不要求共享触摸实现。两者都遵循“拖动预览、松手一次 seek”。

### 7.4 生命周期

- 进入后台暂停的现有行为保持不变。
- 布局切换不能重复创建 `ExoPlayer` 或 `SyncEngine`。
- 页面销毁时释放手势回调、自动隐藏任务、播放器与网络资源。
- 所有延时任务在离开播放页后移除，防止旧任务操作新页面。

## 8. 横竖屏、系统栏与平板实施

### 8.1 手动方向

- 首页和竖屏播放页使用固定竖向。
- 全屏按钮切换到固定横向；退出恢复竖向。
- 不采用 `sensor` 自动旋转。
- 当前 Manifest 已声明 `orientation|screenSize|keyboardHidden`，实施时需验证目标 SDK 和实际设备上的行为，不能只依赖声明推断。

### 8.2 全屏与 Insets

- 横屏沉浸隐藏状态栏和导航栏，用户系统手势仍可使用。
- 顶部与底部控制按实际 Insets 放置，不用固定 24dp 猜状态栏高度。
- 刘海屏确保返回、房间码和全屏按钮不进入裁切区。
- 竖屏恢复系统栏和原主题颜色。

### 8.3 亮度与音量

- 亮度通过当前窗口参数调整，记录进入播放页时的值，退出时恢复。
- 音量使用 `AudioManager.STREAM_MUSIC`，限制在系统最小/最大范围。
- 音量 UI 读取系统真实值；外部音量键变化时同步刷新。
- 两者不调用 `SyncEngine`。

### 8.4 平板资源

- 使用 `smallestWidth`/资源限定符和实际可用宽度选择布局，不用设备型号判断。
- 双栏侧栏设置合理最大宽度，视频区域优先分配空间。
- 横屏手机和平板尽量复用控制层，只有成员容器和尺寸需要差异化。

## 9. 风险与预防

| 风险 | 预防与定位 |
|---|---|
| 横滑连续 seek 导致卡顿 | `onMove` 只更新 UI；日志确认松手仅一次 seek |
| 本地与远端 seek 来回覆盖 | 远端 seek 使手势失效；保留回声抑制 |
| 单击与双击延迟混乱 | 画面单击允许短等待，实体按钮立即响应 |
| 手势与进度条争夺触摸 | 控件优先消费，画面控制器不拦截子控件事件 |
| seek 被误判为暂停 | 回归现有 `playWhenReady` 和 buffering 判断 |
| 横竖屏切换重建播放器 | 实机检查 player 实例、房间成员和播放位置 |
| 深色主题文字不可见 | 不依赖主题默认色，关键文字显式使用设计令牌 |
| 平板只是手机拉伸 | 600dp 专项截图验收双栏和抽屉 |
| Toast 与新手势提示重叠 | 同步消息统一进入消息层，禁止手势期间堆叠 Toast |
| 返回直接退房 | 横屏先退全屏，竖屏确认离开 |
| 中文路径构建失败 | 继续使用现有 `build-apk.bat` ASCII 临时目录机制 |

### 10.4 性能观察

- 横滑期间主线程无持续解码和大量对象分配。

- 平板布局切换不重新加载视频。
- 长时间播放无旧 Handler 任务累积。
- 中低端设备优先保证手势反馈和播放流畅，再考虑装饰效果。

## 12. 后续执行方式

建议严格按 **阶段 1 首页 → 阶段 2 控制层 → 阶段 3 seek → 阶段 4 横屏与锁定 → 阶段 5 平板 → 阶段 6 回归** 执行，每个阶段单独验收。不要同时重写同步引擎，也不要为了视觉改版顺带迁移 Compose。

下一次开始编码时，先从阶段 0 和阶段 1 入手；手势实施前再单独审查一次 `PlayerGestureController` 的状态转换和 `SyncEngine` 上报链路。这样最容易把 UI 问题、触摸问题和多人同步问题分开定位。
