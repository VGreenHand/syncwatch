# ledger-rotation — SyncWatch 账本轮转与保留

> 派生自 `https://gitee.com/VGreenHand/my-skill` 的 `ledger-rotation` 通用模板，2026-11-10 按 SyncWatch 落地。

本 skill 规定 **`PROGRESS.md` 的流水历史怎么切、怎么压、什么能删**。它不改账本的状态值（当前状态 / 下一步 / 最近刷新）——那些由当前工作线的收尾人写。

## 适用对象

符合 `session-handover`「账本契约」的 `PROGRESS.md`（§0 入口 / §12 流水 / 单写者 / 证据指针 / 状态机）。当前账本约 10 KB，远低于阈值，**不需要轮转**。

## 触发

- **时点**：里程碑 / 阶段切换收尾时，由维护者或收尾人触发。**不在每次任务收尾检查。**
- **硬判据**：§12 流水 > 40 条，或 `PROGRESS.md` > 60 KB。
- 未触发就什么都不用做。本 skill 不是每次会话的必读项。

## 轮转动作

1. 建 `docs/archive/`；项目若已有归档区，沿用其位置与命名习惯。
2. 把最老的一段流水切到 `docs/archive/PROGRESS-YYYYQn.md`，例：`docs/archive/PROGRESS-2026Q4.md`。
3. 归档文件顶部加横幅：`> **[历史流水]** 记录当时做了什么，可查证；开工依据见主账本与文档权威图。`
4. 主账本 §12 保留最近约 20 条；在 §12 顶部维护「历史索引」表（区间 → 文件 + 日期）。
5. **切段不得改动节号**——编号连续是跨文件追溯的唯一锚点。
6. §0 入口节补一行轮转提示，使入口里指向已归档节号的引用仍能定位（否则会变成悬空指针）。

## 分层保留

| 层 | 内容 | 策略 |
| --- | --- | --- |
| 永久（压缩索引） | 决策与后果、ADR 指针、未闭环项、不可逆操作的证据指针 | 每周期压成数行，永久留在主账本 |
| 限期（原文归档） | 实现细节、门禁数字、逐轮修复过程、真机测试记录 | 进季度归档；更早的可在后续周期再压 |
| 可丢 | 重复的状态描述、已被入口节覆盖的投影、中间命令输出 | 压缩时不留 |

## 删除条件

**删除的唯一条件是两条同时成立**：① 已被压缩索引覆盖；② 版本控制可回溯（原文本在提交历史里可查）。
缺一条就不删。**若项目未纳入版本控制，本 skill 的删除动作一律不执行**——那等于真丢。

**永不删清单**

- ADR 与决策翻案记录（例：LiveKit 方案被后续推翻的那次翻案本身）。
- 不可逆操作的证据指针（切换部署、凭据轮换、数据清空、服务器迁移）。
- 未闭环项与挂账项——删了欠账就消失。
- v0.6 语音的验收记录与真机测试数据；发布后仍需可追溯。

## 与 session-handover 的分工

- `session-handover`：每次接力的读协议、任务级收尾契约、状态机。
- 本 skill：里程碑级的账本轮转与压缩。两者都不改对方的职责。

## 移植到新项目

1. 本 skill 与 `session-handover` 是一对，一起复制到新仓库的 `.agents/skills/`。
2. 确认新项目已有账本；没有就按 `session-handover` 的账本契约先建 §0 入口与 §12 流水。
3. 按项目规模调整硬判据与保留窗口（SyncWatch 默认 40 条 / 60 KB / 保留 20 条）。
4. 确认账本与归档区都在版本控制内，否则删除条件不成立。
