# ledger-rotation — 账本轮转与保留

本 skill 规定账本历史**怎么切、怎么压、什么能删**。它**不改**账本状态值——那些由该工作线当次的收尾人按 `session-handover` 写。

本文件是通用件：不含任何仓库的阈值、路径或窗口。项目值来自目标仓库 `AGENTS.md` 的「会话交接配置」节。

## 第 0 步：加载配置

读 `<repo>/AGENTS.md` 的「会话交接配置」节，取出：`账本`、`流水节`、`轮转`（阈值 / 归档目录 / 保留窗口）。`轮转` 为「未启用」时本 skill 不适用，直接停止。任一项缺失就停下报告，不要猜。

## 适用对象

符合 `session-handover`「账本契约」五项的账本。没有账本的项目先建账本，再谈轮转。

## 触发

- **时点**：里程碑 / 阶段切换收尾时，由验收方或收尾人触发。**不在每次任务收尾检查**，本 skill 也不是每次会话的必读项。
- **硬判据**：按配置 `轮转` 的节数阈值与文件大小阈值；两者取「或」。
- 未触发就什么都不做。

## 轮转动作

1. 建配置指定的归档目录；项目已有归档区时沿用其位置与命名习惯。
2. 把最老的一段流水切到 `archive/<账本名>-<年季>.md`。
3. 归档文件顶部加横幅：`> **[历史流水]** 记录当时做了什么，可查证；开工依据见主账本与文档权威图。`
4. 主账本保留配置指定的最近窗口；在流水区顶部维护「历史索引」表（区间 → 文件 + 日期）。
5. **切段不得改动节号**——编号连续是跨文件追溯的唯一锚点，也是「取最大流水号」在轮转后仍然成立的原因。
6. 入口节补一行轮转提示（指向归档文件），否则入口节里指向已归档节号的引用会变成悬空指针。

## 分层保留

| 层 | 内容 | 策略 |
| --- | --- | --- |
| 永久（压缩索引） | 决策与后果、ADR 指针、未闭环项、不可逆操作的证据指针 | 每周期压成数行，永久留在主账本 |
| 限期（原文归档） | 实现细节、门禁数字、逐轮修复过程、真机测试记录 | 进季度归档；更早的可在后续周期再压 |
| 可丢 | 重复的状态描述、已被入口节覆盖的投影、中间命令输出 | 压缩时不留 |

## 删除条件

**唯一条件是两条同时成立**：① 已被压缩索引覆盖；② 版本控制可回溯（原文本在提交历史里可查）。缺一条就不删。

**若项目未纳入版本控制，本 skill 的删除动作一律不执行**——那等于真丢。

**永不删清单**

- 决策与翻案记录（包括「结论被后来推翻」的那次翻案本身）。
- 不可逆操作的证据指针（切换部署、凭据轮换、数据清空、迁移）。
- 未闭环项与挂账项——删了欠账就消失。
- 项目配置 `附加纪律` 中点名保留的证据（如验收记录、真机数据）。

## 与 session-handover 的分工

- `session-handover`：每次接力的读协议、任务级收尾契约、状态机、副本翻转。
- 本 skill：里程碑级的账本轮转与压缩。两者都不改对方的职责。

## 移植到新项目

1. 与 `session-handover` 成对复制到 `<repo>/.agents/skills/`（轮转依赖账本契约判断「压缩索引是否已覆盖」）。
2. **不要改动本文件**。在 `AGENTS.md` 的「会话交接配置」节填 `轮转` 的阈值、归档目录、保留窗口。
3. 确认账本与归档区都在版本控制内，否则删除条件不成立。
