# session-handover — 会话级交接

分段 agent 开发最贵的开销不是干活，是**重建上下文**：被迫通读越写越长的状态文档，注意力被历史淹没（lost-in-the-middle、多日期基线冲突、指令漂移）。

本 skill 用三个机制解决：**入口节**（只存指针与唯一值）、**单写者收尾契约**（只追加流水 + 刷新入口）、**里程碑级轮转**（配套 `ledger-rotation`）。

本文件是**通用件**：不含任何仓库的路径、节号、任务号或阈值。所有项目值来自目标仓库 `AGENTS.md` 的「会话交接配置」节。

## 第 0 步：加载配置（每次会话必做，先于其他一切）

1. 读目标仓库根目录 `AGENTS.md`，找到标题含 `会话交接配置` 的节。
2. 按下表逐项取值；**任一项缺失或为空就停下报告，不要猜、不要套用别的项目的值。**
3. 配置与账本实际结构不一致时（例如配置里的节号在账本中不存在），同样停下报告，不要自行「修正」账本。

**`AGENTS.md` 不存在、或没有该配置节时**：说明本项目尚未接入。不要自行编造配置开工，改为走下方「首次接入一个仓库」，按其步骤先勘察、再提案、等确认。

| 配置键 | 用途 |
| --- | --- |
| `工作线` | 当前分支 / 工作线名；账本随分支走时说明哪份是施工副本 |
| `账本` | 账本文件路径（相对仓库根） |
| `入口节` | 入口节标题（含节号） |
| `流水节` | 流水标题格式 + 取最大号的命令 |
| `任务清单` | 需随收尾翻转的任务表位置；无则写「无」 |
| `任务文档路由` | 按任务 / 章节查「开工前读哪些文件」的对照表位置；无则写「无」 |
| `状态副本` | 收尾时须一并翻转的其他副本；无则写「无」 |
| `证据位置` | 流水内证据写到哪（commit / 产物 / 证据目录） |
| `状态机` | 状态取值与顺序 |
| `权威链` | 冲突仲裁顺序（从高到低） |
| `收尾提交` | commit 前缀与形态约定 |
| `轮转` | 阈值与保留窗口；未启用写「未启用」 |
| `附加纪律` | 本仓库特有的硬规则（授权门槛、ADR 状态、禁止事项等） |

## 账本契约（五项，缺一不可）

任何要被本 skill 接管的账本，必须同时具备：

| 项 | 要求 |
| --- | --- |
| 入口节 | 当前状态 / 下一步 / 最近刷新（节号）/ 阻塞项去向；只存指针与唯一值，纯值 ≤ 15 行 |
| 流水节 | 有稳定编号规则；**节号连续、只增、轮转不改号** |
| 单写者 | 只有该工作线当次的收尾人能写 |
| 证据指针 | 每条流水指向可复核的证据（commit / 命令输出 / 产物路径 / 真机记录） |
| 状态机 | 见配置 `状态机`；默认 `⬜ 未开始 → 🚧 实现中 → ⏸ 阻塞(等待 X) → 🔶 待验收 → ✅ 已验收` |

一条工作线一个账本，互不写入。实验线收束（并入 / 挂账 / 放弃）时才回主线账本补一条。

## 权威链

按配置 `权威链` 从高到低仲裁。默认形状：

```
永久决策（ADR / 领域词表）
  > 计划原文（验收条件唯一来源）
  > 任务卡 / 当次任务文档（边界）
  > 流水 + 证据（做了什么、验证到什么程度）
  > 入口节（投影，纯消费方）
```

- 入口节每个动态值标注来源流水号。
- 入口节落后于最新流水时，**以最新流水为准**，口头提示「入口节滞后 N 条」，**不得动手改**。
- 指向状态的地方只放路径 / 引用，**不准复制状态值**——复制即双写漂移。

## 启动读取协议（每次时段开始 / 接力会话）

1. 确认工作线：checkout 到配置 `工作线` 指定的分支，再读该分支上的账本。分支不符时先确认意图，不要直接开工。
2. 读账本 `入口节`（约前 25 行）与 `任务清单` 中当前任务行。**不通读全文、不读历史流水。**
3. 用配置 `流水节` 的命令取最大流水号，与入口节「最近刷新」比对；滞后则按上文处理。
4. 只读入口节与 `任务文档路由` 指明的文件：当次任务文档、任务卡、必要时领域词表。不读其他任务文档、不通读文档目录。
5. 需要历史细节时，按流水号精确定位，不做全文检索式浏览。

## 写纪律（单写者）

只有**当前工作线当次的收尾人**能写账本。一次收尾 commit 内做完：

1. append 一条流水（编号 = 上一条 + 1）；
2. 按该条取值刷新入口节（状态、最近刷新、最新基线、下一步）；
3. 翻转配置 `任务清单` 对应行；配置 `状态副本` 非「无」时一并翻转。

其他会话（含接力会话）发现入口节过期：**只口头报告，不得改写**。接力会话默认只读。

## 收尾契约（双时刻状态机）

- **实现方收尾**：按上文三件事写入 → 状态置 `🔶 待验收` → 单次收尾 commit，前缀按配置 `收尾提交`。
  - 证据必须可复核：commit、命令与结果、产物路径、真机型号与系统版本、环境事实。没有验证的部分显式写「未验证」，不用「应该可以」代替证据。
- **验收方通过**：在流水条上补「✅ 已验收 + 决策」→ 再刷入口节（状态=✅、最新基线/下一步更新）。
- 实现与验收同日且验收方在场时可合并为一次收尾 commit；**但实现 commit 内禁止预写 ✅**。
- `⏸ 阻塞` 的「等待 X」必须写清**等谁、等什么**，否则接力会话会把「等人」误当「可执行」。
- 流程 / 文档类收尾若不改变当前任务状态：入口节状态值保持不变，只刷新版本、最近刷新、最新基线、导航。
- 账本过长**不在本契约内处理**：轮转是里程碑级动作，见 `ledger-rotation`。

## 验收核对（人眼）

- 入口节各动态值 = 最近流水条的值，且来源节号指向该条。
- 任务清单 / 状态副本对应行与入口节一致。
- README、文档、任务说明中没有复制状态值。
- `⏸` 条目有「等待谁 / 等什么」的去向指针。

## 触发时机

- 每次时段**开始**（加载配置 → 启动读取协议）。
- 每次任务收尾（实现方收尾 / 验收方通过两个时刻）。
- **里程碑或阶段切换收尾**时，另外触发 `ledger-rotation` 检查是否需要轮转。

## 移植到新项目

1. 把本文件复制到 `<repo>/.agents/skills/session-handover/SKILL.md`；需要轮转时把 `ledger-rotation/SKILL.md` 一并复制。**不要改动这两个文件。**
2. 在 `<repo>/AGENTS.md` 新增「会话交接配置」节，13 个键填本仓库真实值。
3. 确认账本已具备账本契约五项；没有就按契约先建入口节与流水节。
4. 在 AGENTS.md 其余位置不再重复交接流程细节，只留一句指向本 skill 的指针。
5. 升级时直接覆盖 `SKILL.md` 为新版本，配置节不受影响——这是本结构存在的理由。

## 首次接入一个仓库（配置节不存在时）

目标是**把仓库里已有的事实填进配置，而不是发明一套新流程**。全程先勘察、再提案，改文件前等人工确认。

### 1. 先判断该不该接入

- 项目是否长期、有阶段推进、会换机器或换会话接力？一次性小活不值得接入。
- 是否已有某种状态文件（进度、状态、计划、README 里的 roadmap）？没有的话，接入成本高于收益时直接建议不上。

### 2. 勘察这 13 个值（只读，不改任何文件）

| 配置键 | 从哪里找 | 找不到时 |
| --- | --- | --- |
| `工作线` | `git branch -a`；AGENTS.md / README 里对当前阶段的描述 | 单线项目写「单线，分支 `<默认分支>`」 |
| `账本` | 仓库里记录进度与验收的文件：`*PROGRESS*`、`*STATUS*`、`docs/plans/*`、roadmap | 见第 3 步 |
| `入口节` | 账本顶部是否有「现在在哪 / 下一步」式小节 | 见第 3 步 |
| `流水节` | 账本里按时间累积、带序号的标题；注意标题级别与编号格式 | 见第 3 步 |
| `任务清单` | 账本或单独文件里的任务状态表 | 写「无」 |
| `任务文档路由` | AGENTS.md / README 是否说明「做 X 读哪些文件」 | 写「无」，读取时只依赖入口节 |
| `状态副本` | 同一状态是否还写在 README、路线图、章文件头 | 写「无」，并在第 4 步把副本改成指针 |
| `证据位置` | 有无 `evidence/`、`docs/evidence/`；流水里是否已写 commit | 写「流水内写 commit 与命令结果」 |
| `状态机` | 账本里实际用到的状态符号 | 用本 skill 的默认五态 |
| `权威链` | AGENTS.md 里的「冲突时以谁为准」；ADR / 设计文档目录 | 按默认形状裁剪，去掉不存在的层 |
| `收尾提交` | `git log --oneline -20` 看前缀习惯；AGENTS.md 有无提交规则 | 跟随现有历史的主导前缀 |
| `轮转` | 账本当前体量与流水条数 | 体量小就写「未启用」，别提前引入归档 |
| `附加纪律` | AGENTS.md 中原有的硬规则：授权门槛、密钥边界、不可逆操作 | 写「无」 |

勘察结论要给**证据**：每个值后面标出处（文件 + 行号，或命令输出）。找不到就明确写「未找到」，不要用常识补。

### 3. 账本不存在时：先问，再建

不要为了接入 skill 擅自造一个账本。先报告「本项目没有状态账本」，给出两个选项让人选：

- **A. 不接入**：保持现状，本 skill 不适用。
- **B. 建最小账本**：新建一个文件，含入口节（状态 / 下一步 / 最近刷新 / 阻塞去向）+ 流水节（`## 流水 1` 起步）+ 证据指针。历史进度从现有文档里搬，不重写。

选 B 时，账本内容必须来自仓库已有事实（git log、现有计划、README），不允许编造进度。

### 4. 落地顺序

1. 把 `SKILL.md`（以及需要时的 `ledger-rotation/SKILL.md`）复制到 `<repo>/.agents/skills/`。
2. 在 `AGENTS.md` 新增「会话交接配置」节，填第 2 步勘察到的值。
3. 若原有 AGENTS.md 里有重复的交接流程描述，压缩成一句指向本 skill 的指针——**不要留下两套规则**。
4. 若 `状态副本` 非「无」，把副本改成指针（只写「状态见 <账本> <入口节>」）。
5. 用一次真实任务做试跑：读入口节 → 干活 → 按收尾契约写一条流水，确认入口节与流水号能对上。

### 5. 不确定就问

以下情况必须停下来问，不要自行决定：

- 仓库里有多个候选账本，分不清哪个是权威。
- 现有状态文件的结构与本 skill 的账本契约冲突（例如没有独立入口节、状态散落多处）。
- 流水编号格式不统一，无法确定「最大号」怎么算。
- 项目是否长期维护本身不清楚。
