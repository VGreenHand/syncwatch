# session-handover — SyncWatch 会话级交接

> 派生自 `https://gitee.com/VGreenHand/my-skill` 的 `session-handover` 通用模板，2026-11-10 按 SyncWatch 落地。

SyncWatch 是「Go 信令服务器 + Windows(mpv) + Android(Media3)」的本地片源同步观看项目。当前唯一活跃工作线是 **v0.6 Android 内置语音**，施工分支 `feat/android-voice`，发布基线 `main`。

本 skill 规定**什么时候读什么、什么时候写什么、冲突听谁的**。它不是会话压缩：目标是让接力会话只读 `PROGRESS.md` §0 与当次任务文档即可开工，避免通读全文导致的 lost-in-the-middle、多日期基线冲突与指令漂移。

## 角色

| 角色 | 是谁 | 职责 |
| --- | --- | --- |
| 维护者 | 人类（项目所有者、验收方） | 定范围、拍板 ADR、上真机/服务器验收、决定是否发布 |
| 实现会话 | agent（施工方、账本收尾方） | 读入口、实现任务、运行门禁、收尾写账本 |
| 接力会话 | 后续 agent | 默认只读；读入口后继续施工，发现入口滞后只报告 |

## 账本契约（五项，缺一不可）

| 项 | 本项目落地位置 |
| --- | --- |
| 入口节 | `PROGRESS.md` §0 会话入口：只存指针与唯一值，动态值标〔流水 12.N〕 |
| 流水节 | `PROGRESS.md` §12 的 `### 12.N — 标题`；编号连续、只增；**轮转不改号** |
| 单写者 | 当前 checkout 分支的收尾方；同一分支同一时间只在一台机器活跃 |
| 证据指针 | 每条流水内写 commit / PR / 构建产物 / 真机或服务器记录；本项目不另建证据目录 |
| 状态机 | ⬜ 未开始 → 🚧 实现中 → ⏸ 阻塞(等待 X) → 🔶 待验收 → ✅ 已验收 |

- **工作线**：当前只有 v0.6 语音一条。账本 `PROGRESS.md` 随分支走：`feat/android-voice` 是施工副本，`main` 是发布副本；只写当前 checkout 的副本。
- **未来新工作线**：在对应分支的 `docs/branches/` 下另立账本，并在其入口节登记；不得与语音线共用同一份可写账本。

## 权威链（冲突时按此仲裁）

```
docs/adr/（永久决策）
  > README 红线 + docs/01（范围与不可逆边界）
  > PROGRESS.md §1–§3 + §7（当前工作线目标、边界、验收条件）
  > docs/02、03、04、05、06、07、08（协议、部署、客户端实现事实）
  > PROGRESS.md §12 流水 + 证据（做了什么、验证到什么程度）
  > PROGRESS.md §0 入口（投影，纯消费方）
```

- 入口节每个动态值标〔流水 12.N〕；落后于最新流水时**以最新流水为准**，并口头提示「入口节滞后 N 条」，**不要动手改**。
- ADR 的 `Proposed` 只代表提案，不等于已批准；只有维护者能把状态改为 `Accepted`。
- README、docs、任务说明里提到当前状态时只放指针，**不准复制状态值**。

## 启动读取协议（每次开发时段开始 / 接力会话）

1. 确认分支：当前工作线应为 `feat/android-voice`；若在 `main`，先确认是否要做发布/验收，不要直接在 `main` 写施工流水。开工前按 `PROGRESS.md` §10 更新分支；落后于 `main` 时先 `git merge main`，避免 rebase 改写已推送的共享分支。
2. 读 `PROGRESS.md` **§0 会话入口**（约前 25 行）与 §7 的任务状态表中当前任务行；**不通读全文、不读历史流水**。
3. 比对最新流水号：`Select-String -Path PROGRESS.md -Pattern '^### 12\.'`（git bash 用 `grep '^### 12\.' PROGRESS.md`）。若最大号大于入口节「最近刷新」，以最新流水为准继续，并提示滞后条数。
4. 只读当次任务需要的文档：
   - T1 LiveKit 部署：ADR §5/§7 + `docs/03-服务端部署.md` + `voice/`（待建）
   - T2 服务器下发 token：ADR §4 + `docs/02-同步协议.md` + `server/main.go`
   - T3 Android 接入：ADR §6 + `docs/05-Android客户端.md` + `docs/07`/`08` + `android/` 相关源码
   - T4 双机联调：ADR「验收标准」+ `docs/05` 的已知限制
   - T5 文档：`docs/02`、`docs/05`、`README.md` 的对应章节
5. 不读其他任务文档、不读历史流水、不通读 `docs/` 全部文件。

## 写纪律（单写者）

只有**当前分支的收尾方**能写 `PROGRESS.md`，一次收尾 commit 内做三件事：

1. 在 §12 append 一条 `### 12.N — 一句话标题`（N = 上一条 + 1）；
2. 按该条取值刷新 §0 入口节（状态、最近刷新、下一步、已验证/未验证、当前占用）；
3. 翻转 §7 任务状态表对应行（状态 + 证据指针）。

其他会话（含接力会话）发现入口节过期：**只口头报告，不得改写**。接力会话默认是只读会话。

## 收尾契约（双时刻状态机）

- **实现方收尾**：按上文三件事写入 → 任务状态置 **🔶 待验收** → 单次 `docs:` 或 `feat(v0.6):` commit。
  - 证据必须可复核：commit、构建命令与结果、APK/镜像路径、真机型号与系统版本、服务器命令输出摘要。
  - 没有验证的部分显式写「未验证」，不要用「应该可以」代替证据。
- **维护者验收**：在流水条上补「✅ 已验收 + 决策」→ 再刷 §0（状态=✅、最新基线/下一步更新）。
- 实现与验收同日且维护者在场时可合并为一次收尾 commit。
- ⏸ 阻塞的「等待 X」必须写清**等谁、等什么**（如「等待维护者确认 LiveKit 镜像版本」），否则接力会话会把「等人」误当「可执行」。
- 本项目允许收尾提交；提交前缀跟随仓库习惯：`feat(v0.6): 中文描述`、`fix: 中文描述`、`docs: 中文描述`。
- **账本过长不在本契约内处理**：轮转是里程碑级动作，见 skill `ledger-rotation`（本项目阈值：流水 > 40 条 或 `PROGRESS.md` > 60 KB）。

## 验收核对（维护者/人眼）

- 入口节各动态值 = 最近流水条的值，且〔流水 12.N〕指向该条。
- §7 任务状态表对应行的状态/证据与入口节一致。
- README、docs 没有复制当前状态值；`PROGRESS.md` 内只有 §0/§12 是动态状态，§4 已静态化，§9 只放开放问题。
- ⏸ 条目有「等待谁/等什么」的去向指针。
- ADR 状态变更只由维护者执行；`Proposed` 文档不能当已批准方案施工。

## 触发时机

- 每次开发时段**开始**（读入口节 → 启动协议）。
- 每次任务收尾（实现方收尾 / 维护者验收两个时刻）。
- **里程碑或阶段切换收尾**（如 v0.6 语音合入 `main`、切换下一条工作线）时，另外触发 `ledger-rotation` 检查账本是否轮转。
